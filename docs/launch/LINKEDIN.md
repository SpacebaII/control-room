I built Control Room because most project management demos stop where the difficult work starts.

A task board can show activity. It does not explain why a program is red, what the forecast pressure means, which dependency moved, who owns the response, or what evidence supports the sponsor update.

Control Room is a working operations PMO suite built around a fictional regional rollout. It connects:

- integrated milestones and execution work
- RAID and decision registers
- budget, commitments, forecast, and capacity
- change assessment and sponsor approval
- evidence-backed status reporting
- simulated Slack, Teams, and email workflows
- mobile assignments, approvals, messages, and files

The public version gives every visitor an isolated 24-hour workspace. Its PM copilot is deterministic, adapts to changed project records, and costs nothing to demonstrate. A private owner mode can use OpenAI, but it only returns cited proposals. It cannot change project data until a manager selects and accepts the proposed records.

The most useful development problems were not flashy ones. Spreadsheet rendering exposed broken header contrast. Accessibility checks forced changes to the signal palette. Two-session tests proved one visitor could not alter another visitor's demo. Optimistic versions made stale updates fail visibly instead of overwriting project controls.

That is the part I wanted the portfolio project to show: not just that I can assemble a UI, but that I can make product, architecture, security, and operating decisions fit together.
